Payroll ADP Integration — Value Mapping (Proposed Approach)

Document: Proposal for how translatable values could be configured, for team review
Proposed navigation: Human Resources > Compensation > Payroll integration > Payroll ADP value mapping
Status: Draft proposal — August 2026 — pending review and approval

This document describes a proposed design for handling the translatable and static values required by the integration. It is put forward for the team to review and is not yet approved. Adopting it would represent an addition to the original FDD scope.

1. Purpose

The proposed Value Mapping table would translate values between D365 and ADP Celergo. When the batch process extracts employee data, it would look up each configurable value in this table and send the configured Target value to ADP instead of the raw D365 value.

The intent is to let the business define and update translations without code changes or redeployment, and to answer the open hardcode-versus-configurable question raised on 12 August.

2. Proposed Table Structure

ColumnDescription
CategoryDropdown. Selects which group of values this row belongs to.
Source valueThe value as D365 knows it, or a fixed technical key (see Section 4).
Target valueThe value that will be sent to ADP. You define this based on ADP requirements.
DescriptionOptional. Free text for your own reference.

3. Two Proposed Types of Source Value

TypeSource valueTarget valueApplies to
Fixed Key A predefined technical key. Type it exactly as documented (case-sensitive). You define this based on what ADP requires. Static Value, Funding Method, "FIXED_COMP"
Lookup A value that exists in D365. The form provides a dropdown with available options. You define this based on what ADP requires. Gender, Marital Status, Type of Contract, FT/PT, Pay Element Code (plans), Termination Reason, Nationality
In both cases, the Target value would be the business's responsibility. The system would never generate it. You would enter what ADP expects to receive.

5. How a Row Would Be Added or Modified

If the approach is adopted, maintaining a value would look like this:

  1. Open the form (at the proposed navigation path above).
  2. Click New.
  3. Select the Category.
  4. Enter or select the Source value.
  5. Enter the Target value.
  6. Save.

Changes would apply on the next batch run automatically.

6. Notes and Assumptions

  • The table would be per legal entity, so you would switch company for other entities.
  • If a row were missing, for most categories the D365 value would pass through unchanged. For Pay Element Codes, the plan would be excluded.
  • Target values shown as "e.g." are examples taken from the current design and mapping spreadsheet. Final values would need to be confirmed with ADP before entry.
  • This is a proposed approach for review. If approved, it would be an addition to the original FDD scope and would carry a revised estimate.
