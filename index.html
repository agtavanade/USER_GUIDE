Payroll ADP Integration — Value Mapping User Guide

Navigation: Human resources > Compensation > Payroll integration > Payroll ADP value mapping
Scope: Per legal entity. Switch company to maintain another entity.
This guide describes what the feature does. Where behaviour differs between categories, the difference is called out rather than generalised, because two categories behave in opposite ways when a row is missing (see Section 7).

1. Purpose

The Value Mapping table translates values between D365 and ADP Celergo. When the batch extracts employee data it looks up each configurable value in this table and sends the configured Target value to ADP instead of the raw D365 value.

It also holds a number of fixed constants that the design specifies but that D365 has no field for. The business maintains all of them without code changes or redeployment.

2. Table Structure

ColumnDescription
CategoryDropdown. Selects which group of values the row belongs to. Eight categories exist.
Source valueThe value as D365 knows it, or a fixed technical key (see Section 3).
Target valueThe value sent to ADP. You define this from the ADP requirement.
DescriptionOptional. Free text for your own reference.

Category and Source value together form the alternate key CategorySourceIdx, so the same source value cannot be entered twice within one category.

3. Two Types of Source Value

TypeSource valueApplies to
Fixed key A predefined technical key, read directly by the code. Type it exactly as documented, it is case sensitive. Static Value (6 keys), Funding Method (DEFAULT), Pay Element Code (FIXED_COMP)
Lookup A value that exists in D365. The form offers a dropdown of the available options. Gender, Marital Status, Type of Contract, Full Time / Part Time, Termination Reason, Pay Element Code (variable compensation types)
In both cases the Target value is the business's responsibility. The system never generates it. Enter exactly what ADP expects to receive.

4. The Eight Categories

These are the only categories that exist. There is no Nationality category: nationality is sent straight through, because the D365 country region id is already the three character ISO code ADP expects.

5.5 Type of Contract (lookup)

The source is the Benefit employment type id on the worker's employment details, not the worker type. The worker type only distinguishes an employee from a contractor, which is too coarse to carry these values. Source values are therefore whatever benefit employment types are configured in D365, for example Permanent or FixedTerm.

5.7 Pay Element Code (mixed)

Two different things live in this category and they behave in opposite ways.

Base pay, the fixed key FIXED_COMP.

Source valueTarget valueIf left empty
FIXED_COMPAwaiting ADPThe PAYD record is still sent, carrying the real salary amount and no pay element code. The validator raises a warning and transmission continues.

Variable compensation awards, by type. The source value is the variable compensation type id on the award's plan, not the plan id.

Source valueTarget valueIf left empty
Variable compensation type id from D365e.g. H10153The award is skipped entirely, no PAYD record is produced for it.
A missing row here is silent. The award simply does not appear in the payload, with no warning. Every variable compensation type in use needs a row, or its awards are invisible to ADP.
Variable compensation enrolments are out of scope, confirmed with the functional team. The code exists but is not called, so enrolments never reach the payload regardless of what is configured here. Only awards are live.

7. What Happens When a Row Is Missing

There is no passthrough. An unmapped source value returns empty, never the D365 value. This is deliberate: most categories are read by a fixed key defined in code, so passing the source value through would put the key itself, for example WORK_LOCATION, into the payload as if it were payroll data.
CategoryResult of a missing or empty row
Static Value, used for a CSPF fieldEmpty value, and a country specific field with no value produces no CSPF record at all. The field is silently absent from the payload.
Static Value, the two identification keysThe extract cannot find the identification record, so the CSPF field is empty and again produces no record.
Gender, Marital Status, Type of Contract, Full Time / Part Time, Termination ReasonEmpty value, so no CSPF record for that field.
Funding MethodThe BANK record is still sent with an empty funding method.
Pay Element Code, FIXED_COMPThe PAYD record is still sent, with the amount and no code. Validator warning.
Pay Element Code, a variable compensation typeThe award is skipped. No record, no warning.

The practical consequence: a missing row fails silently. Nothing errors, the payload is simply smaller. Check the record counts after the first run rather than waiting for an error.

8. Adding or Changing a Row

  1. Confirm you are in the correct legal entity.
  2. Open Human resources > Compensation > Payroll integration > Payroll ADP value mapping.
  3. Click New.
  4. Select the Category.
  5. Enter the fixed key, or select the D365 value from the lookup.
  6. Enter the Target value.
  7. Save.

Changes apply on the next batch run. No deployment is required.

9. Notes

  • The table is per legal entity. Configuring one entity does nothing for another.
  • Target values shown as "e.g." come from the design and the mapping spreadsheet. Confirm the final values with ADP before entering them.
  • The value mapping table was added during the build. The design required translated values but defined no mechanism to hold them.
