Payroll ADP Integration - Value Mapping Configuration Guide

For: the functional team configuring the ADP payroll extract
Navigation: Human resources > Compensation > Payroll integration > Payroll ADP value mapping
Scope: Per legal entity. Switch company to configure another entity.
Version: 24 September 2026

This guide lists every value that has to be configured before the extract can produce a complete payload, exactly as it has to be typed, and what happens to the payload if a value is missing. Section 8 is a checklist you can work through before the first run.

1. What this table does

ADP Celergo expects its own values, which are not always the values D365 holds. The Value Mapping table is where you define that translation. Each time the extract runs, it reads this table and sends your Target value to ADP in place of the D365 value.

It also holds a number of constants that apply to every employee and that D365 has no field for, such as the geographical zone.

Changes take effect on the next run. Nothing needs to be deployed.

2. The form

The grid has four columns, in this order:

#ColumnWhat goes in it
1CategoryA dropdown. Choose which group of values the row belongs to. Eight categories exist, listed in Section 3.
2DescriptionOptional. Free text, for your own reference. Never sent to ADP.
3Source valueThe value as D365 holds it, or a fixed key from this guide.
4Target valueThe value ADP receives. You define this from the ADP requirement.

The same Source value cannot be entered twice within one Category.

Only two categories give you a dropdown in the Source value column: Pay Element Code and Termination Reason. For every other category you type the Source value by hand. It is case sensitive and there is no validation, so a typo does not raise an error, it simply produces an unmapped value. Section 7 explains what that costs you.

4. What to configure, category by category

4.1 Static Value

Six rows. Type each Source value exactly as shown below.

Source value (type exactly)Target valueWhat it does
REMUNERATION_TYPEe.g. SalariedSent as TYPE OF REMUNERATION
WORK_LOCATIONe.g. Buenos Aires - Florencio VarelaSent as WORK LOCATION
GEOGRAPHICAL_ZONEe.g. Buenos Aires - Florencio VarelaSent as GEOGRAPHICAL ZONE
OCCUPATION_CODEe.g. 1049Sent as OCCUPATION CODE
IDENT_TYPE_NATIONAL_IDe.g. DNINot sent to ADP. Tells the extract which identification type on the worker holds the national ID
IDENT_TYPE_SOCIAL_SECURITYe.g. CUILNot sent to ADP. Tells the extract which identification type holds the CUIL
The last two behave differently from the rest. Their Target value has to match an Identification type id in D365 exactly, not partially. And the worker's identification record itself has to be current: if it carries an issue date in the future or an expiry date in the past, the extract treats it as not applicable and the field goes out empty even though your mapping is correct.

4.7 Pay Element Code

This category covers two different things.

Base pay. One row, typed.

Source value (type exactly)Target value
FIXED_COMPPending confirmation from ADP

Variable compensation awards. One row per variable compensation type in use. This is the one place with a real dropdown: it lists the variable compensation plans and shows the plan id and description so you can identify them, but what it stores is the plan's type. Several plans sharing a type therefore need only one row between them.

Source valueTarget value
Select from the dropdownThe ADP pay element code, e.g. H10153
An award whose type has no row here is left out of the payload entirely, with no message of any kind. Every variable compensation type in use needs a row, or those awards never reach ADP.

Variable compensation enrolments are out of scope for this integration. Only awards are sent.

4.8 Termination Reason

One row per reason code in use. The dropdown lists D365 reason codes and shows only those flagged as applicable to termination, so a reason code that does not appear needs that flag set in D365 first.

The first time the form is opened in a legal entity, the eight fixed-key rows are created for you, with the Target value left blank:

Pay Element CodeFIXED_COMP
Two things to know about this.
  • A blank Target value is not a configured value. All eight still have to be filled in.
  • They are only created while the table is completely empty. If the first thing you do in a new legal entity is add a Gender row, the eight will never appear and you will have to type them yourself. Open the form first, let the eight appear, then start adding your own rows.

Gender, Marital Status, Type of Contract, Full Time / Part Time, Termination Reason and the variable compensation types are never created for you.

7. What happens if a value is missing

An unmapped value never falls back to the D365 value. It produces an empty result, and an empty country specific field produces no record at all. The field does not arrive at ADP blank, it simply is not there.
What is missingEffect on the payload
A Static Value row used for a country specific fieldThat field is absent for every employee
An identification type key, or the wrong value in itThe national ID or CUIL is absent for every employee
A Gender, Marital Status, Type of Contract or Full Time / Part Time rowThat field is absent for the employees holding the unmapped value only
Funding MethodThe bank record is still sent, with the funding method blank
FIXED_COMPThe payment record is still sent, with the salary amount and no pay element code
A variable compensation typeThose awards are left out of the payload entirely
Nothing above produces an error. The run completes and the payload is simply smaller. The way to catch it is to compare the record counts after the first run against what you expect, rather than waiting to be told.

Two related points that are not about this table but cause the same kind of silent gap: an employee with no bank account marked as remainder produces no bank record, and an employee with no primary postal address produces almost no address record.

9. Adding or changing a row

  1. Confirm the legal entity.
  2. Open Human resources > Compensation > Payroll integration > Payroll ADP value mapping.
  3. Click New.
  4. Choose the Category.
  5. Enter the Source value. Pay Element Code and Termination Reason offer a dropdown, everything else is typed and case sensitive.
  6. Enter the Target value.
  7. Save.

The change applies on the next run.
